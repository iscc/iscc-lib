# Next Work Package

## Step: Migrate PyO3 0.26 → 0.27 (issue #1, incremental toward 0.29)

## Goal

Advance the workspace `pyo3` pin one minor version (`0.26 → 0.27`) toward the `0.29.0` target that
clears the two RustSec advisories shipped inside the published Python wheel. One reviewed minor per
step keeps each migration small and bisectable; this is the next hop in the in-progress migration
tracked by issue #1 ("Update PyO3 0.23 → 0.29").

## Scope

- **Modify**: `Cargo.toml` (workspace dep pin on line 35, `pyo3 = { version = "0.27", ... }`)
- **Modify**: `crates/iscc-py/src/lib.rs` (ONLY if 0.27 introduces new deprecations/breaking changes
    that `-D warnings` flags — the only binding file with a PyO3 dependency; may need zero edits, as
    0.24 and 0.25 hops required none)
- **Modify (generated, not counted)**: `Cargo.lock` (regenerated by `cargo update -p pyo3`)
- **Reference**: `.claude/context/handoff.md` (proven recipe + 0.26 review notes), PyO3 migration
    guide https://pyo3.rs/main/migration, `crates/iscc-py/pyproject.toml` (maturin config — confirm
    no version edit needed; it only lists the `pyo3/extension-module` feature)

## Not In Scope

- Do NOT jump multiple minors in one step (no 0.27 → 0.28 → 0.29). One reviewed minor per step.
- Do NOT refactor the raw `pyo3::ffi::*` CPython C-API sites (`PySequence_List`, `PyList_GetItem`,
    `PyLong_AsLong`, `Bound::from_owned_ptr`, `downcast_into_unchecked`) — they map to stable
    CPython C API and have survived every hop. Only touch them if `-D warnings` forces it.
- Do NOT touch the CRAP `--fail-above 30` hardening (issue #2, HUMAN REVIEW REQUESTED) or the
    `iai-callgrind` perf gate (issue #3) — separate steps.
- Do NOT expect the RustSec advisories to clear at 0.27 — they clear only at 0.29 (2 hops away).
    That is expected, not a verification failure for this step.

## Implementation Notes

- Recipe (proven on the 0.23→0.24, 0.24→0.25, 0.25→0.26 hops):
    1. Edit `Cargo.toml` line 35: `pyo3 = { version = "0.27", features = ["abi3-py310"] }`.
    2. `cargo update -p pyo3` to regenerate `Cargo.lock` (also bumps pyo3-ffi/build-config/macros/
        macros-backend to 0.27.x).
    3. Build + lint + format: `cargo build -p iscc-py`, `cargo clippy -p iscc-py -- -D warnings`,
        `cargo fmt --all --check`.
    4. Resolve any new 0.27 deprecation warnings surfaced by `-D warnings` in
        `crates/iscc-py/src/lib.rs` idiomatically (the 0.26 hop renamed `allow_threads` → `detach`
        and switched `PyObject` → `Py<PyAny>`; current file has 7 `detach` + 17 `Py<PyAny>` and 0
        `allow_threads`). Preserve GIL-release semantics at the 7 compute call sites.
    5. Verify the wheel builds and tests pass via maturin + pytest.
- Preserve `abi3-py310` on the workspace dep — single wheel per platform, Python 3.10+.
- `pyproject.toml` carries no pyo3 version (only the `pyo3/extension-module` maturin feature) — it
    should need no change; confirm by inspection.
- Run `uv run mdformat --wrap 100 --number` (or `mise run format`) before committing to avoid the
    pre-push mdformat hook reformatting context files.

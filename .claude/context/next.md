## Step: Dependency refresh slice 7 — Ruby manifests (`Gemfile` + `Gemfile.lock`)

## Goal

Refresh the Ruby development dependencies of `crates/iscc-rb` to their latest versions installable
on Ruby 3.1 (rake, standard/rubocop, rubocop-minitest and their transitives), while pinning `rb_sys`
exactly at `0.9.123` with a documented `# held:` comment so it can never silently drift away from
the `oxidize-rb/actions/cross-gem` Docker image tag in `release.yml`. This is the last
CID-actionable, fully locally-verifiable slice of the `normal` `[human]` issue "Dependency review
and refresh across the project".

## Implementation Notes

**Baseline confirmed by the scoper (working tree as it stands):** `bundle exec standardrb` exits 0,
`bundle exec rake test` → `111 runs, 299 assertions, 0 failures, 0 errors, 0 skips`. Ruby 3.1.2,
Bundler 2.6.9, `libclang-14` and a prebuilt `lib/iscc_lib/iscc_rb.so` are all present in the
devcontainer, so every gate below is runnable locally.

**Running bundler** — there is no `-C` equivalent; use a subshell so the repo root stays the working
directory, e.g. `(cd crates/iscc-rb && bundle exec standardrb)`. `crates/iscc-rb/.bundle/config`
sets `BUNDLE_PATH: vendor/bundle` (gitignored), so installs stay local to the crate.

**Step 1 — pin `rb_sys` first, then update.** In `crates/iscc-rb/Gemfile` change
`gem "rb_sys", "~> 0.9"` to an exact `gem "rb_sys", "0.9.123"` with an inline comment in the
project's hold-back style, naming *why*: `rb_sys` bundles `rake-compiler-dock` (`= 1.10.0`) whose
`cross_rubies` patch-version map must match the `oxidize-rb/actions/cross-gem` Docker image
`tag: 0.9.123` in `release.yml`; 0.9.124+ ships a Ruby 4.0 build tool that breaks
`RbSys::ExtensionTask`. Add a second `# held:` comment on the `minitest "~> 5.0"` line stating that
minitest 6.x requires Ruby >= 3.2 while the gem supports >= 3.1.

**Step 2 — refresh.** Run `(cd crates/iscc-rb && bundle update)`. With `rb_sys` pinned exactly, the
resolver should move roughly: `rake` 13.3.1 → 13.4.2, `standard` 1.54.0 → 1.56.0, `rubocop` 1.84.2 →
1.88.2, `rubocop-minitest` 0.39.1 → 0.40.0, plus transitives (`json` 2.21.1, `parser` 3.3.12.0,
`regexp_parser` 2.12.0, `rubocop-ast` 1.50.0, `parallel` 1.28.0, `language_server-protocol`
3.17.0.6). `rake-compiler` 1.3.1 and `minitest` 5.27.0 are already the newest allowed. Do not
hand-edit `Gemfile.lock`; let bundler write it. `PLATFORMS` (`ruby`, `x86_64-linux`) and
`BUNDLED WITH 2.6.9` should stay as they are.

**Step 3 — lint fallout.** `standard` 1.56 / `rubocop` 1.88 may surface new offenses in
`lib/**/*.rb`, `test/**/*.rb`, `Rakefile`, `extconf.rb` or the gemspec.
`bundle exec standardrb --fix` is fine for mechanical fixes; read the resulting diff. **Fix the
code, never silence the rule** — do not add entries to `.standard.yml`, do not add
`# rubocop:disable` comments, do not exclude files. If a new rule cannot be satisfied without a real
behavior change, stop and report it in the handoff rather than suppressing it.

**Step 4 — doc sync.** Update the "rb_sys Version Pinning" section of `crates/iscc-rb/CLAUDE.md` so
it states that the version is now pinned exactly in **both** `Gemfile` and `Gemfile.lock` and must
be changed together with `tag:` in `release.yml`. Keep it to a couple of lines.

**Verification-order tip:** run `standardrb` before `rake compile`/`rake test` — the compile step is
the slow one, and a lint failure is cheaper to find first.

**If a brand-new gem release lands mid-step** and `bundle outdated --strict` still reports something
after the update, either take it (if it passes all gates) or hold it with an inline `# held:`
comment giving the reason — never leave an undocumented gap.

# Next Work Package

## Step: Refresh Rust `Cargo.lock` (cargo update) — dependency-refresh slice 1 (Rust ecosystem)

## Goal

First per-ecosystem slice of the open `normal` `[human]` issue **"Dependency review and refresh
across the project"** (v0.6.0 target; spec `ci-cd.md` → "Dependency Freshness"). Regenerate the Rust
`Cargo.lock` so 100+ transitive/direct deps move to their latest **semver-compatible** patch/minor
releases within the existing `Cargo.toml` caret constraints, with every quality gate staying green.
This satisfies the Rust half of the spec's "Lockfiles regenerated on the refreshed set" criterion
without any risky pin-crossing.

## Scope

- **Modify**: `Cargo.lock` (regenerated by `cargo update` — a generated lockfile, not a hand-edited
    source file; does not count toward the 3-file budget)
- **Reference**: `Cargo.toml` (workspace.dependencies — must stay unchanged), `deny.toml`,
    `.claude/context/specs/ci-cd.md` ("Dependency Freshness"), `.iai-baseline.json`,
    `.crap-baseline.json`, `.github/workflows/ci.yml` (perf + deny gate steps)

## Not In Scope

- **Do NOT edit `Cargo.toml` `[workspace.dependencies]` pins.** No crossing a major or 0.x-minor
    boundary this step — specifically leave `uniffi = "0.31"` (0.32.0 is available but needs Swift/
    Kotlin re-verify), `pyo3 = "0.29"` (held for #41), `criterion = "0.5"`,
    `iai-callgrind = "0.16"`, `magnus = "0.7"` (rb_sys/Docker-tag constraint), `jni = "0.21"`, and
    `napi = "3"` at their current pins. Direct-pin evaluation + documented hold-back reasons is a
    **separate follow-up step** ("Rust direct-pin evaluation").
- Python `uv.lock`, npm/Ruby/Java/Kotlin/.NET/Go manifests, tooling pins (`mise.toml`,
    `.pre-commit-config.yaml`, GHA versions) — each is its own per-ecosystem step.
- Flipping the `Semver` gate to enforcing or cutting v1.0.0 — both deliberately held by Titusz.
- Refreshing `.crap-baseline.json` — this step changes **no source**, so CRAP is unaffected.

## Implementation Notes

- Run `cargo update` with **no `-p` filter** to refresh the whole lockfile within existing caret
    ranges. Expected moves include `uniffi 0.31.0 → 0.31.2` (patch within the `0.31` caret — safe;
    do NOT jump to 0.32), `napi 3.8.3 → 3.11.0`, `blake3 1.8.3 → 1.8.5`,
    `xxhash-rust 0.8.15 →   0.8.18`, `wasm-bindgen 0.2.125 → 0.2.126`, `serde 1.0.228 → 1.0.229`,
    plus ~100 transitive updates. Confirm the resulting diff is `Cargo.lock`-only (`Cargo.toml`
    byte-identical).
- **cargo-deny is the main risk.** `cargo update` can pull a new transitive dep whose license is not
    on the allow-list, or surface a fresh RustSec advisory — either flips the enforcing
    `Audit (cargo-deny)` gate red. Run `mise run audit` (= `cargo deny check`, already installed at
    0.19.9). If one crate trips it, prefer `cargo update -p <crate> --precise <patched>` (check the
    advisory's `patched` range first) over broadening `deny.toml`; only add a license to the
    allow-list if it is clearly acceptable and note why. Do **not** add a blanket ignore to mask a
    real advisory.
- **Perf-gate contingency (CI-only gate):** transitive bumps (esp. `blake3`) can shift iai-callgrind
    Ir counts. The gate tolerates ≤10% drift vs `.iai-baseline.json`. Run `mise run bench:iai:check`
    locally (valgrind + iai-callgrind-runner are installed); if it fails on **legitimate dependency
    drift** (not a source regression — no source changed here), refresh the baseline in this SAME
    step via `mise run bench:iai:baseline`, same discipline as the CRAP-baseline rule. Do not widen
    the 10% epsilon.
- No source, docs, or public-API changes — purely a lockfile refresh. If any test/gate fails for a
    reason other than deny/perf drift, stop and reassess rather than editing source.

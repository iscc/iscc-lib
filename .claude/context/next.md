## Implementation Notes

**Go module refresh**

- From the repo root (never `cd`), use `-C`:
    `go get -C packages/go -u ./... && go mod tidy -C packages/go`. Expected resulting `go.mod`:
    `golang.org/x/text v0.40.0` (direct), `github.com/klauspost/cpuid/v2 v2.4.0` (indirect),
    `github.com/zeebo/blake3 v0.2.4` unchanged.
- `golang.org/x/text v0.40.0` declares `go 1.25.0`, which is below the module's `go 1.26.1`, so no
    `go`-directive bump or `toolchain` line should be introduced. If Go adds one anyway, revert that
    single line by hand and re-run `go mod tidy`.
- **Real conformance risk, and the reason this slice is worth running:** `x/text` ships Unicode
    tables, and `packages/go/utils.go` uses `unicode/norm` (NFKC) inside `TextClean`, which feeds
    every `Gen*CodeV0`. A table change could shift Meta/Text-Code output. The vendored vectors in
    `packages/go/testdata/data.json` are the guard — `go test` must stay green. **If a conformance
    test fails, hold `golang.org/x/text` back** (`go get -C packages/go golang.org/x/text@v0.34.0`)
    with an inline `// held:` comment above the `require` block naming the failing vector, and
    report it in the handoff. Never edit a vector, a test, or `data.json` to make the bump pass.
- `go.sum` is generated — let `go mod tidy` write it; do not hand-edit.

**version_sync `TARGETS` entry**

- Append `("packages/kotlin/README.md", _get_doc_dep_version, _sync_doc_deps),` to the `TARGETS`
    list in `scripts/version_sync.py`, next to the other `_get_doc_dep_version` entries (after
    `("packages/swift/README.md", ...)` is fine). `GRADLE_DEP_RE`
    (`io\.iscc:iscc-lib(?:-kotlin)?:\d+\.\d+\.\d+`) already matches line 13 of that README, so no
    regex change is needed.
- Then run `mise run version:sync` to rewrite `0.3.1` → `0.5.0`, and `mise run version:check` to
    confirm. Do not hand-edit the README — letting the script do it proves the wiring works.

**Recording the napi/dotnet closure**

- Do not modify `crates/iscc-napi/package.json` or the `.csproj` files. Instead, state in the
    handoff that both were re-checked and are current (with the versions you observed), so the
    review agent can strike them from the slice ledger in `issues.md`. Leave `issues.md` itself to
    the review agent.

**Order of work:** Go first (it can fail and force a hold-back), then the version-sync wiring, then
`mise run format` before staging.

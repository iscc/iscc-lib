## Implementation Notes

- Run `uv lock --upgrade` at the repo root to re-resolve all dev-group deps to the latest compatible
    versions (the dev deps are unconstrained, so this pulls the newest available of each).
- Then rebuild + verify against the refreshed set: `uv sync --group dev` →
    `uv run maturin develop --manifest-path crates/iscc-py/Cargo.toml` (the extension must be built
    for `pytest` to import `iscc_lib`).
- **Biggest risk = unconstrained dev tools jumping a major and changing behavior**: a `ruff` bump
    can add/alter lint or format rules (`ruff check` / `ruff format --check` fail), `mdformat` can
    reformat markdown (`prek`/`mise run check` rewrites files), `ty` can surface new type errors,
    and `zensical`/`mkdocstrings` can break the docs build.
- **How to handle a break (in priority order):** (1) if it is a trivial, correct formatter/lint
    delta, the cleanest path for a *lockfile* slice is to keep source untouched by **pinning that
    one tool back** to its pre-upgrade major in `pyproject.toml` with an inline hold-back comment
    (e.g. `"ruff<0.14",  # held: 0.14 reformats … — refresh with a dedicated step`); (2) never
    disable a lint rule, skip a test, lower coverage, or weaken a gate to accommodate a bump. Prefer
    a single documented hold-back over source churn so the diff stays a lockfile refresh.
- **`iscc-core`**: the vendored `crates/iscc-lib/tests/data.json` is the authoritative conformance
    baseline; the Python comparative tests must still pass against whatever `iscc-core` resolves to.
    If a new `iscc-core` changed outputs (unlikely — ISO 24138 is frozen), pin it back and note why.
- After the refresh, run `mise run format` before staging (pre-push mdformat runs on the whole push
    range and will otherwise reject the batch).

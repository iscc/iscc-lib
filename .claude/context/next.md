# Next Work Package

## Step: Bump the Kotlin package's Gradle wrapper from 8.12.1 to 9.6.1

## Goal

Take the next authorized major from the "Dependency review and refresh" issue: move
`packages/kotlin` onto the current Gradle 9 line. This clears the standing KGP "Deprecated Gradle
Version" warning and puts the JVM build on a supported base before the JUnit 6 migration lands on
top of it.

## Alternatives Considered

- **Chosen:** the Gradle wrapper major — one build system, one failure mode, tool-generated diff,
    and fully verifiable locally (`./gradlew` works here, JDK 17.0.19 present). Gradle 9 also
    *removes* the auto-injected `junit-platform-launcher`, so having the wrapper current first makes
    the JUnit 6 step's failures attributable.
- **Rejected:** the JUnit 6.x migration — it spans two build systems (`build.gradle.kts` +
    `crates/iscc-jni/java/pom.xml`) and renumbers the platform artifacts 1.x→6.x; doing it on a
    wrapper that KGP already deprecates would mix two failure modes in one review.
- **Rejected:** `jni` 0.22 / `magnus` 0.8 — real source rewrites; each is its own step and both are
    riskier than the two JVM build-tooling items.

## Scope

- **Modify** (hand-edited, 1 source file): `packages/kotlin/build.gradle.kts` — only the comment
    above `testRuntimeOnly(...junit-platform-launcher:1.14.4)`, which currently justifies the
    launcher with a Gradle-8.12.1-specific reason. Under Gradle 9 an explicit launcher on the test
    runtime classpath is *required* by Gradle itself; keep the dependency and the `// held:` JUnit
    6.x note, restate the reason.
- **Modify** (regenerated by the `wrapper` task, not hand-edited):
    `packages/kotlin/gradle/wrapper/gradle-wrapper.properties`,
    `packages/kotlin/gradle/wrapper/gradle-wrapper.jar`, `packages/kotlin/gradlew`,
    `packages/kotlin/gradlew.bat`.
- **Modify** (docs): `packages/kotlin/CLAUDE.md` line 38 — `Gradle 8.x` prerequisite is stale.
- **Reference**: `.github/workflows/ci.yml` `kotlin` job (lines 259-274), `release.yml` lines 1200 /
    1230 / 1324 (`./gradlew build`, `test`, `publishMavenPublicationToStagingRepository`),
    `.gitattributes`, `.pre-commit-config.yaml` file-hygiene block.

## Not In Scope

- **Do not bump the Kotlin Gradle Plugin** (`kotlin("jvm") version "2.4.10"`). A KGP bump stamps a
    new metadata version into the published jar and moves the consumer floor — human-only
    (decisions.md 2026-07-25, floor "Kotlin 2.3 or newer").
- JUnit 6.x / `junit-platform` 6.x in either manifest; `crates/iscc-jni/java/pom.xml` stays
    byte-untouched. JNA, gson and Maven-plugin versions stay.
- Do **not** persist `distributionSha256Sum` in `gradle-wrapper.properties` and do not add a
    `gradle/actions/wrapper-validation` CI step — worthwhile, but its own step.
- Do not enable the configuration cache or add `org.gradle.*` tuning flags to `gradle.properties`.
- Do not touch `java-version` in the workflows, `maven.compiler.*`, or
    `.claude/context/specs/kotlin-bindings.md` (human-owned). Do not edit `issues.md` (review owns
    it) — put the slice note in the handoff instead.

## Implementation Notes

- Two-pass upgrade so the jar and scripts are regenerated *by* the new version: run
    `packages/kotlin/gradlew -p packages/kotlin wrapper --gradle-version 9.6.1` twice (`-p` avoids
    `cd`; `bin` is already the default distribution type).
- First run downloads ~130 MB (network works here); `--offline` will fail until it is cached — the
    warm `~/.gradle` only holds 8.12.1. Optional provenance check, no tree change: sha256 of the
    cached `gradle-9.6.1-bin.zip` should be
    `9c0f7faeeb306cb14e4279a3e084ca6b596894089a0638e68a07c945a32c9e14` (from
    `https://services.gradle.org/versions/current`).
- Measured while scoping, so do not re-derive: `kotlin-gradle-plugin` 2.4.10's
    `GradleCompatibilityCheck` carries exactly two constants — `minSupportedGradleVersion` 7.6.3 and
    `nextMinimumSupportedGradleVersion` 8.14.4. There is **no upper bound**, so 9.6.1 is accepted
    and 9.6.1 > 8.14.4 is what retires the deprecation warning.
- Gradle 9 needs JVM 17+ for the daemon only; local JDK is 17.0.19 and CI is temurin 17, so this is
    not a consumer-floor move.
- Gradle generates `gradlew.bat` with CRLF, but this repo stores it LF (`.gitattributes` +
    `mixed-line-ending --fix=lf`). Run `mise run format` before `git add` and keep LF.
- `./gradlew test` can report UP-TO-DATE and silently not execute — always `clean`/`cleanTest`.
    Gradle flakes on this bind mount: on an error, read `build/test-results/test/*.xml` and re-run
    after `clean` before calling it a failure.
- If a residual `Deprecated Gradle features were used in this build` notice appears from KGP itself,
    it is not fixable inside these files — report it in the handoff rather than working around it.
    If 9.6.1 breaks the build outright, fall back to the highest working 9.x, say which and why.

- `mise run check` exits 0 and modifies no file.

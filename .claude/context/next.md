    un-bisectable. Use `uv lock --upgrade-package ruff`.

    0.16, so nothing needs fixing, and a blanket `--fix` deletes the 13 load-bearing

    `combine-as-imports` settings, and do not delete the deliberately redundant pre-push
    `--select S` / `--select C901` hooks (kept on purpose in sub-slice B).
- Do not bump `.pre-commit-config.yaml`'s `mdformat rev: 1.0.0` or its `additional_dependencies` —

## Implementation Notes

All facts below were measured live at HEAD during scoping.

**1. The edit.** `pyproject.toml` line 47 currently reads:

```text
  "ruff<0.16",                    # held: 3 findings left under 0.16 (RUF007 in …, PLW1510 in …, EXE001 on tools/cid.py) — drop the pin once they are cleared
```

Replace the whole line with `  "ruff",` (no comment — the hold-back is over). Then:

```bash
uv lock --upgrade-package ruff
```

PyPI's latest ruff is exactly **0.16.0**, so the lock resolves to it. Two places in `uv.lock`
change: the `{ name = "ruff", specifier = "<0.16" }` requirement entry (loses its specifier) and the
`name = "ruff"` package block (`0.15.22` → `0.16.0` with new hashes). Nothing else should move — if
`git diff --stat uv.lock` shows other packages, you ran the wrong command.

**2. What actually changes at 0.16, measured.**

- `uvx ruff@0.16.0 check .` already exits 0 (`All checks passed!`) — sub-slice D cleared the last
    three findings, so the linter side is a no-op.
- Hook-mode and gate-mode both stay green under 0.16: `check $(git ls-files '*.py' '*.pyi')`,
    `check --select S --force-exclude` and `check --select C901 --force-exclude` each exit 0.
- **The one real behaviour change is the formatter's file discovery.** ruff 0.16 formats Python code
    blocks embedded in Markdown, so `uv run ruff format --check` (bare — the exact command in
    `mise run lint` and `ci.yml`) goes from `25 files already formatted` to
    `153 files already   formatted`. All 129 tracked `.md` files are already clean under 0.16
    (`uvx ruff@0.16.0 format --check $(git ls-files '*.md')` → exit 0), so this widening costs
    nothing today and is free coverage for documentation examples. Call it out explicitly in the
    handoff so it does not read as accidental scope.
- `ruff check` does **not** lint Markdown (`check README.md` → "No Python files found"), so only the
    formatter's surface widened.
- Gitignored trees are still skipped: `reference/` (32 files would reformat) and `cauldron/` (1) are
    excluded from a bare `.` invocation — do **not** "fix" them, and do not pass explicit paths that
    would pull them in.

**3. If `ruff format` does reflow something.** The measurement above says it will not, but if
`uv run ruff format --check` reports any file after the bump, apply `uv run ruff format` and treat
the churn as part of this step (it is the cost of the upgrade) — then say so explicitly in the
handoff rather than letting it look like unrelated noise. Never reach for `--fix` to solve a
formatting complaint.

**4. Gate interactions.** No Rust, Go, JVM, .NET, Ruby or WASM source is touched, so the CRAP
regression baseline, iai-callgrind perf gate, `cargo-deny` and `cargo-semver-checks` are all
untouched by this step — do not refresh `.crap-baseline.json` or `.iai-baseline.json`.

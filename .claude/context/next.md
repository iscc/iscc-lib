# Next Work Package

## Step: Repair the Ruby source gem step — declare rb_sys only in the staged source gem

## Goal

Repair the NEEDS_WORK step from iteration 239 ("The Ruby source gem cannot be built", `normal`) on
top of the unpushed commit `d299106`: the unconditional `rb_sys` gemspec dependency puts a
version-less `rb_sys (~> 0.9)` line first in `Gemfile.lock`. That breaks the version lookup of
`cross-gem@v1` and gives every platform gem a runtime dependency. Same goal, narrower design.

## Alternatives Considered

- **Chosen:** conditional `rb_sys` dependency (the review's recommended branch). It restores the
    `Gemfile.lock` of `d299106~1` and leaves the platform gems with no runtime dependency, as the
    published 0.7.0 gems have. It must land before anything else, because review pushes only on PASS
    and `d299106` sits unpushed at HEAD
- **Rejected:** keep the dependency unconditional and rewrite the "Link Gemfile.lock" step in
    `release.yml`. The platform gems would gain a runtime `rb_sys` (+ `rake-compiler-dock`)
    dependency that nothing tests before a release, and `release.yml` never runs in CI
- **Rejected:** the derived-fact drift issue (`normal`). It is unrelated, and the unpushed broken
    commit has to be repaired first

## Implementation Notes

- **Gemspec:** declare the dependency only in the staged tree, e.g.
    `spec.add_dependency "rb_sys", "~> 0.9" if File.directory?(File.join(__dir__, "core"))`. Use
    `__dir__`, not the cwd, so `Gem::Specification.load` from another directory gives the same
    answer. Update the comment so it says why the dependency is conditional: the platform gems are
    precompiled and need no `rb_sys`, and a dependency here would break the `cross-gem` lock lookup.
    The dependency is fixed when `gem build` runs in the stage, so the installed source gem keeps it
- **Lock:** run `bundle install` in `crates/iscc-rb`. The `PATH` → `specs:` block must lose the
    `rb_sys (~> 0.9)` line, so `git diff d299106~1 -- crates/iscc-rb/Gemfile.lock` is empty
- **Test the real lookup:** `cross-gem@v1` runs
    `grep rb_sys Gemfile.lock | head -n 1 | grep -oE '[0-9]+\.[0-9]+\.[0-9]+'`. The match is
    unanchored: the first line that contains `rb_sys` anywhere wins. Delete
    `test_gemfile_lock_pins_cross_gem_rb_sys`. Add a pure helper in the test module that copies that
    pipeline on lock text: first line containing `rb_sys`, first `X.Y.Z` in it, `None` if there is
    none. Then add tests:
    1. On the real `Gemfile.lock`, the helper equals the Gemfile `gem "rb_sys", "…"` pin and the
        `tag:` input of the `oxidize-rb/actions/cross-gem` step in `release.yml` (read it with
        `yaml`)
    2. A fire test: a minimal lock whose `PATH` specs carry `rb_sys (~> 0.9)` before the `GEM` section
        returns `None` (the `d299106` shape). Inline the text, do not run `git show`
- **Gemspec dependency shape:** replace `test_gemspec_carries_core_and_depends_on_rb_sys` with a
    test that loads the real gemspec through `ruby -e`. In `crates/iscc-rb` it must have no runtime
    dependencies. In a `tmp_path` copy (the gemspec, `lib/iscc_lib/version.rb` and an empty `core/`
    directory) it must have exactly `rb_sys` with a `~>` requirement. `gemspec_files()` already
    needs `ruby`, so this adds no new tool. No skip markers
- **`run()`:** pass `stdout=subprocess.PIPE` instead of `capture_output=True`, so stderr reaches the
    job log. Update the docstring. Also fix the review nit: `gemspec_files()` splits on lines
    (`splitlines()`), not on any whitespace
- **CLAUDE.md:** Publishing must describe the conditional dependency, say why, and say that platform
    gems have no runtime dependencies. "rb_sys Version Pinning" must state the real unanchored
    lookup (the first line containing `rb_sys` must carry the pinned version) and name the test that
    guards it
- Python and Ruby files only: the CRAP, iai and semver gates are not affected

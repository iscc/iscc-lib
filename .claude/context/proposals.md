## Align pre-commit vs pre-push mdformat config (or format-before-commit in define-next) — risk: needs-human

**Observation:** Context-file markdown (`next.md`, per-agent `MEMORY*.md`) can pass the pre-commit
mdformat auto-fix yet be rejected by the pre-push mdformat check, which runs with different args
(`--wrap 100 --number`, `mdformat-mkdocs[recommended]`). A non-conforming file rejects the whole
batch push, forcing the review agent to reformat + amend.

**Evidence:** Documented in `learnings.md` ("Pre-push mdformat blocks on non-conforming context
files", added ~iter 111). Surfaced visibly at least once in the last 200 commits: `758fc31`
(`cid(review): ... normalize context-file mdformat for pre-push gate`, iter 93). define-next's
commit step (step 10, `define-next.md:85-90`) does not run `mise run format` first.

**Proposed change:** Preferred root-cause fix — make the pre-commit and pre-push mdformat hooks in
`.pre-commit-config.yaml` use identical args so what passes commit passes push. Lower-effort
alternative — add a `mise run format` step before the commit in `define-next.md` (and
`update-state.md`).

**Hypothesis:** Eliminates the occasional review reformat-and-amend cycle — **Metric:**
median_turns, expect a small decrease (fewer review unblock cycles).

**Why not auto-applied:** The config fix touches `.pre-commit-config.yaml` (a quality gate —
proposal-only). The define-next variant modifies a commit instruction, which the whitelist excludes
from prose-only auto-edits. Low frequency, so low urgency.

## iteration_summary logging gap on failed/interrupted iterations — risk: needs-human

**Observation:** The durable `iteration_summary` series — the input to meta-improve's rollback
metrics — is missing rows for iterations 95, 103, and 106. Iteration 106 had a `review` `FAIL` row,
so the summary was never written; 95 and 103 are likewise absent.

**Evidence:** `grep "iteration_summary"` of `iterations.jsonl` shows a continuous series 88→111
except 95/103/106; `iterations.jsonl` has a `review` `status:FAIL` row at iter 106
(`2026-06-18T01:28:27`).

**Proposed change:** In `tools/cid.py`, emit an `iteration_summary` row (with a status/incomplete
flag) even when an iteration aborts on a role failure, so the metric series has no index gaps.

**Hypothesis:** Makes meta-improve's before/after `window` comparisons span truly adjacent
iterations rather than silently skipping failed ones — improves the fairness of auto-rollback
judgement. **Metric:** n/a (robustness of the measurement itself, not a loop metric).

**Why not auto-applied:** Any change to `tools/cid.py` (control flow / logging / schema) is
proposal-only.

## Keep zero-turn iteration summaries out of the median_turns metric — risk: needs-human

**Observation:** Two `iteration_summary` rows report `turns_total: 0` with a real verdict, and
`_window_metrics` in `tools/cid.py` includes them when it computes the median. It leaves out only
`FAILED` verdicts. A 0 in a window is not an effort measurement, so it would skew the rollback
judgement on any future meta change whose window contains one. The skew can go either way: a 0 in
the "after" window can hide a regression, and a 0 in the "before" window can cause a false revert.

**Evidence:** Iterations 195 and 212 each have exactly one role row: `review`, `status: TIMEOUT`,
`turns: 0`, `recovered: true` (3363 s and 3327 s). Their summaries are `PASS_WITH_NOTES` with
`turns_total: 0`. The neighbours (196, 211, 213) have all four role rows. The timed-out run emits no
result event, so `turns` is logged as 0. The iteration also started at review, so the summary holds
only that row. Neither has recurred since review got 7200 s in `091dc7c`: no TIMEOUT in iterations
213–248. No meta change has been evaluated against these windows yet.

**Proposed change:** In `_window_metrics` (`tools/cid.py`), leave rows with `turns_total == 0` out
of the median list, the same way `FAILED` rows are left out, and keep them in the rate. Add a
`tests/test_cid.py` case where a zero-turn `PASS` row does not lower the median. An alternative is
to have `append_iteration_summary` mark summaries that contain a `TIMEOUT`/`recovered` role row and
skip those instead.

**Hypothesis:** Rollback judgements on median_turns stop depending on logging artefacts. —
**Metric:** median_turns, expected to be unchanged on clean windows and more accurate on windows
that contain a partial iteration.

**Why not auto-applied:** `tools/cid.py` is path-blocked for meta-improve, and any metric or schema
change is proposal-only. It is not urgent: the defect is latent (2 rows in 55 iterations, none since
the timeout was raised).

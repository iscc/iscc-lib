## 2026-11-21 — One section runner for `conformance_selftest` in Rust and Go

**Done:** Both languages now run all 11 conformance sections through one generic section runner
(lookup, case loop, outcome reporting). Each section supplies only parse + call: Rust closures
returning `Case<T> = Option<(IsccResult<T>, T)>`, Go `run*Case(tc V) (got, want string, err error)`
functions. `conformance_selftest` / `ConformanceSelftest` signatures and results are unchanged.

**Files changed:**

- `crates/iscc-lib/src/conformance.rs`: `run_section<T: PartialEq + Debug, F>` + generic
    `report_case` (parse / error / mismatch arms, each `eprintln!` once); helpers `expected_iscc`,
    `string_entries`; the 11 `run_*_tests` fns kept as thin wrappers (feature gates kept).
    encode_seq compares lower-case hex strings; decode_seq compares `Vec<String>`. 693 → 398 lines.
    4 new tests
- `packages/go/conformance.go`: generic `runSection[V any]`, `reportCase` (one `switch`, each
    `Fprintf` text once), sentinel `errUnparsable`, `unmarshalInputs(inputs, targets...)`,
    `expectedISCC`, `metaArg`, `streamInputs`; `run*Tests` wrappers removed, `ConformanceSelftest`
    calls `runSection(data, "<section>", run<X>Case)` directly. 638 → 414 lines. `bytes`/`slices`
    imports dropped, `errors` added
- `packages/go/conformance_test.go`: seq tests call `runSection(..., run{En,De}codeSeqCase)` (intent
    unchanged); new `genCase` helper + `TestGenSectionsRun`, `TestGenSectionMissingFails`,
    `TestGenSectionPositiveCase`, `TestGenSectionFailureArms` (5 cases, one per call)
- `.crap-baseline.json`: regenerated by `mise run crap:baseline`; diff touches only `conformance.rs`
    entries (11 removed, 14 added)

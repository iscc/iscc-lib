## 2026-07-29 — Mint `gen_iscc_id_v1` on WASM + settle JS-number input validation (napi & wasm)

**Done:** Added the experimental `gen_iscc_id_v1` minting export to `crates/iscc-wasm` (bare-string,
33 Tier 1 symbols) and settled the JS-number input-validation approach: both JS-number surfaces
(napi + wasm) now take all three params as `f64` and reject non-finite / non-integral / negative /
out-of-range inputs *before* narrowing, via a per-file `checked()` helper. This resolves the
`normal` napi coercion issue and advances #43.

**Files changed:**

- `crates/iscc-wasm/src/lib.rs`: new `gen_iscc_id_v1(f64,f64,f64) -> Result<String,JsError>` +
    private `checked()` validator (after `iscc_decompose`).
- `crates/iscc-napi/src/lib.rs`: signature `(f64,u16,u8)` → `(f64,f64,f64)`; added `checked()`
    validator; docstring updated. (`index.js`/`index.d.ts`/`*.node` are gitignored build artifacts,
    regenerated by `npm run build`, not committed.)
- `crates/iscc-wasm/tests/unit.rs`: +6 `#[wasm_bindgen_test]` (golden, decode round-trip, rejects
    negative / non-integral / non-finite / out-of-range).

    non-finite, out-of-range `2**32`); retained existing high-end cases.

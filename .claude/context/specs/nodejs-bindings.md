# Spec: Node.js Bindings — Native Addon via napi-rs

An npm package `@iscc/lib` providing native Rust-powered ISCC functions via napi-rs (Rust ↔ Node.js
bridge). Follows the same hub-and-spoke model as all other bindings: thin bridge crate wrapping
`iscc-lib` core, with TypeScript declarations for type safety.

## Architecture

**Single-layer design** (simpler than Python/Ruby):

1. **Rust bridge** (`crates/iscc-napi/src/lib.rs`): napi-rs annotated functions that call `iscc-lib`
    core and return JavaScript types (strings, objects, arrays, `Buffer`). All 33 Tier 1 symbols
    exported via `#[napi]` attribute macros.
2. **TypeScript declarations** (`crates/iscc-napi/index.d.ts`): Auto-generated by napi-rs during
    build, providing IDE completion and type checking for consumers.

**Why napi-rs (not wasm-bindgen or N-API C):**

- napi-rs generates native Node.js addons directly from Rust — highest performance
- Auto-generates TypeScript declarations from Rust types
- Handles N-API versioning, async, and Buffer types automatically
- Same architecture as many popular npm native packages (e.g., `@napi-rs/canvas`, `swc`)
- Separate from `@iscc/wasm` which targets browser environments

## Rust Bridge Layer

All functions use `#[napi]` attribute macros. Result types are returned as JavaScript objects:

```rust
#[napi(object)]
pub struct MetaCodeResult {
    pub iscc: String,
    pub name: String,
    pub metahash: String,
    pub description: Option<String>,
    pub meta: Option<String>,
}

#[napi]
pub fn gen_meta_code_v0(
    name: String,
    description: Option<String>,
    meta: Option<String>,
    bits: Option<u32>,
) -> napi::Result<MetaCodeResult> { ... }
```

### Naming Convention

napi-rs auto-converts Rust `snake_case` to JavaScript `camelCase`:

- `gen_meta_code_v0` → `genMetaCodeV0`
- `text_clean` → `textClean`
- `alg_minhash_256` → `algMinhash256`

### Streaming Hashers

`DataHasher` and `InstanceHasher` are exposed as JavaScript classes via `#[napi]`:

```rust
#[napi]
pub struct DataHasher {
    inner: Option<iscc_lib::DataHasher>,
}

#[napi]
impl DataHasher {
    #[napi(constructor)]
    pub fn new() -> Self { ... }

    #[napi]
    pub fn update(&mut self, data: Buffer) -> napi::Result<()> { ... }

    #[napi]
    pub fn finalize(&mut self, bits: Option<u32>) -> napi::Result<DataCodeResult> { ... }
}
```

### Error Handling

Errors are mapped to JavaScript `Error` objects via `napi::Error::from_reason()`. The error message
contains the Rust error description.

## Distribution / Publishing

### npm Publishing

- **Scope**: Published under the `@iscc` npm organization
- **Package**: `@iscc/lib`
- **Authentication**: `NPM_TOKEN` GitHub Actions secret

### Native Binary Distribution

`@iscc/lib` ships as a **single self-contained package** that bundles every platform's native addon
in the published tarball via `files: ["*.node"]`. The auto-generated `index.js` loader detects the
host platform at runtime and `require`s the matching `iscc-lib.<triple>.node`:

| Platform        | Bundled binary                  |
| --------------- | ------------------------------- |
| linux-x64-gnu   | `iscc-lib.linux-x64-gnu.node`   |
| linux-arm64-gnu | `iscc-lib.linux-arm64-gnu.node` |
| darwin-x64      | `iscc-lib.darwin-x64.node`      |
| darwin-arm64    | `iscc-lib.darwin-arm64.node`    |
| win32-x64-msvc  | `iscc-lib.win32-x64-msvc.node`  |

The package declares **no `optionalDependencies`** and publishes **no per-platform sibling
packages**. This is a deliberate departure from napi-rs's default per-platform distribution model:
each stripped addon is only ~1.1 MB, so bundling all five (~5.5 MB) costs little, and it eliminates
the `optionalDependencies` fragility class (placeholder lockfile entries, `npm ci` vs `npm install`
divergence, inconsistent npm/pnpm/yarn/bun handling). The release workflow must therefore **not**
inject `optionalDependencies` (i.e. do not run `napi prepublish -t npm`, or strip the injected block
before `npm publish`) and publishes only the single `@iscc/lib` package.

**Revisit trigger:** if the bundled binaries grow large (e.g. total tarball > ~30 MB from added SIMD
variants or many more target triples), switch to the standard napi per-platform model — publish each
`@iscc/lib-<triple>` package, declare them as `optionalDependencies`, and drop `*.node` from `files`
so consumers download only their platform's binary.

## CI Integration

### CI Job (ci.yml)

```yaml
nodejs:
  runs-on: ubuntu-latest
  steps:
    - uses: actions/checkout@v4
    - uses: dtolnay/rust-toolchain@stable
    - uses: actions/setup-node@v4
      with:
        node-version: 22
    - run: npm ci
      working-directory: crates/iscc-napi
    - run: npm run build
      working-directory: crates/iscc-napi
    - run: npm test
      working-directory: crates/iscc-napi
```
